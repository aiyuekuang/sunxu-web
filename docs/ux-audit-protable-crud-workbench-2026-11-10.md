# ProTable CRUD 列表工作台：现状盘点与设计方案

日期：2026-11-10
状态：已按本方案实现第一版共享组合组件；公开契约以 `docs/component-contracts.md` 和源码 TypeScript props 为准
范围：Sunxu Web（React PC 管理端）+ MES Web 基线 + 东健 CRM Web

## 结论

建议新增一个薄组合层，暂名 `CrudListWorkbench`，直接组合 Sunxu Web 已有的 `ListScreenContainer`、`FilterBar`、`StatusTabs` 与上游 `ProTable`。不从 Ant Design `Table` 重造一套查询/分页框架，也不 fork 或修改 ProTable 源码。

ProTable 能表达的列查询字段优先交给其公开 `search` 配置：`span` 支持响应式断点，`defaultCollapsed`、`defaultFormItemsNumber` 和原生折叠按钮负责字段较多时的渐进展开。CRM 示例里需要业务自控、无标签同行排列的短筛选控件走 `quickFilters` 插槽；Sunxu Web 只补 ProTable 没有的真实容器宽度自动折叠与点击展开行为。[ProTable 搜索表单 API](https://pro-components.antdigital.dev/en-US/components/table/)

它负责列表结果区的结构、筛选与表格能力的组合位置，以及跨项目一致的交互约定；宿主负责请求、字段含义、权限、创建/编辑表单、业务动作、路由和数据策略。高级筛选、保存视图、左侧层级筛选、批量操作均为可选能力，按场景装配。

核心布局规则：

- 常用的一级分类用左侧主 Tab；常用的互斥状态用右侧 `Segmented`；列表动作与结果区紧邻。
- 字段少、低频筛选少的列表保持轻量，不显示空筛选框或视图管理器。
- 多条件列表用右侧高级筛选抽屉；只有层级导航本身是高频任务时才用常驻左侧筛选栏。
- 需要反复切换筛选、排序和列布局的单据列表才启用保存视图。
- 详情明细行上的增删改和字段批量设置属于 `EditableDetailTable`，不并入顶层 CRUD 列表。

### CRM 业务面覆盖

CRM `src/pages/crm/**` 搜到 13 个含表格的文件（其中有嵌套表格/抽屉表格），涵盖 11 个路由业务区：客户、商机、产品、报价、销售订单、拜访、任务、电话、日报、驾驶舱和统计。代码中同时存在简单状态列表、两种对象模式切换、关联记录表格和复杂业务流程页面。

附件产品页代码采用产品主分类 Tab（全部/原材料/半成品/成品），右侧状态单选组（启用中/全部/已停用），并将字典设置、新增产品放在 ProTable 工具栏；分类、状态、关键字合并进入一个请求参数。附件截图中可见 11 个数据列，宽屏下密度较高。CRM 拜访页则通过 Segmented 在“拜访计划/拜访记录”两类任务间切换，并按模式展示日期、负责人、客户及计划状态筛选。CRM 检查范围未发现与 MES 同类的保存视图管理器。

### 现有可复用能力

- **Sunxu Web**：`ListScreenContainer` 已规定“标题 → 紧邻结果区的工具栏 → 结果”；`FilterBar` 提供轻筛选与同级操作插槽；`StatusTabs` 基于 AntD `Segmented` 提供受控互斥筛选；`EditableDetailTable` 负责明细行编辑与按字段批量设置。
- **MES Web**：`DocumentViewBar` 覆盖系统/个人视图的选择、排序、重命名、删除、设默认、保存及脏状态切换；`DocumentFilterDrawer` 是右侧高级筛选抽屉，含已应用条件计数与固定底部操作。12 个单据列表实际接入列表保存视图；台账默认使用轻筛选，只有需要长期保存复杂查询的台账显式启用。
- **MES 列表壳**：`ListPageShell` 组合了请求、列、创建、导入导出、权限、风险分级批量操作、具体表单抽屉和可调列宽。它说明真实列表需要很多能力，但整体带有 MES 单据 API 和权限假设，不宜原样移入通用库。
- **MES / CRM 表格封装**：两个来源仓的 `ResizableTable.tsx` 约 3.7k 行，主体高度相似（行级文本差异约 0.64%），但内部还连着 `useAccess`、导出布局、业务表格工具和列优先级规则。适合把“可调列宽/持久化”等能力单独评估，不适合整体复制为共享 CRUD 工作台。

目标项目当前依赖 React 19.3.1、Ant Design 6.7.0、Pro Components `3.1.15-9` beta；MES/CRM 基线是 AntD 5 + Pro Components 2.x。Pro Components 3 是主版本升级，官方迁移指南明确有破坏性变更和 AntD 6 最低要求，因此复用公共 API 比 fork 2.x 实现更能控制升级边界。

## 现状评审发现

| 级别 | 发现 | 证据与置信度 |
|---|---|---|
| P1（设计约束） | MES `ListPageShell` 适合作为业务参考，不适合作为共享库 API。 | 源码直接包含 MES 权限码、导入导出契约、批次风险等级、MES 表单/请求及视图控制器。代码证据，置信度高。 |
| P1（版本风险） | 不能把 MES/CRM 的 ProTable 2.x 包装直接复制到 Sunxu Web 的 Pro 3 beta。 | 三个仓的依赖基线不同；官方 3.0 迁移指南声明主版本破坏性变更。代码与官方文档，置信度高。 |
| P2（场景适配） | 保存视图和高级筛选是按需能力，不能默认堆到所有列表上。 | MES 12 个列表启用保存视图，而台账默认轻筛选；CRM 现有列表以轻筛选为主。源代码证据，置信度高。 |
| P2（宽度与响应式） | 附件产品列表适合作为宽屏组合范例，但截图不能证明窄屏布局。 | 截图为 1600×900，显示 11 列；CRM 代码另有移动卡片列表。截图内观察 + 源码；移动端实际渲染未在本次检查。 |
| P2（筛选语义） | “筛选侧栏”须区分高级筛选抽屉与常驻左侧分面筛选。 | MES 已证实的是右侧 Drawer；本次代码搜索未找到适用于各业务列表的通用常驻左侧分面侧栏。常驻侧栏应作为可选模式，而不是假定现有规范。 |

## 业界方案对照

| 来源 | 已有能力 | 对本组件的启发 | 不直接照搬的部分 |
|---|---|---|---|
| [Ant Design Table](https://ant.design/components/table/) | 表格数据、分页、排序、筛选、行选择与滚动等基础能力 | 继续将 Table 作为表格原语；由上层声明行选择和列配置 | 自己从 Table 重造完整查询、请求、CRUD 工作台会重复 ProTable 的职责 |
| [ProTable](https://pro-components.antdigital.dev/en-US/components/table/) | 在 AntD Table 上封装请求、查询表单、分页和表格常用行为；支持轻查询与 QueryFilter | 将 ProTable 作为列表运行时；用它已有的 `request`、`params`、`columns`、`actionRef` 等公开契约连接宿主查询 | 不把 ProTable 的每项能力都默认展示，也不将业务字段写进共享组件 |
| [SAP Filter Bar](https://ui5.sap.com/1.38.65/docs/guide/2ae520a67c44495ab5dbc69668c47a7f.html) | 常驻工具栏 + 可折叠筛选区 + Filters 对话框 + 显式 Go；过滤条件可与 variant 组合 | 采用渐进披露；抽屉草稿应有明确应用、重置和取消语义；保存视图与筛选条件可以组合 | SAP 的 variant、服务和桌面/平板/手机规则不作为 Sunxu 的产品契约 |

综合比较：AntD Table 给基础交互，ProTable 给业务列表运行时，SAP Filter Bar 给复杂筛选的渐进披露参考。Sunxu Web 应在 ProTable 上组合自己的列表语义，不维护第三套底层表格。

## 建议场景矩阵

布局不由“字段总数”单独决定，而由筛选使用频率、字段重要性、条件间关系、列表宽度和是否需要保存查询共同决定。下表是建议默认值，宿主可以通过公开配置调整：

| 场景 | 建议布局 | 筛选/表格能力 | 示例及边界 |
|---|---|---|---|
| 少字段、低复杂度主数据 | 轻量工具栏 | 关键字 + 0–2 个高频条件；查询/重置；普通分页 | 基础字典、简单档案。没有字段时不渲染空筛选栏。 |
| 有明确一级业务分类 | 主分类 Tab + 表格 | 分类 Tab 放左侧；状态等次级互斥条件放右侧 Segmented；操作最后 | CRM 产品：全部/原材料/半成品/成品 + 启用状态 + 字典/新增。切换条件重置到第一页。 |
| 中等复杂度运营列表 | 轻筛选 + 高级筛选入口 | 关键字及少数高频条件常驻；不常用条件进 Drawer；显示已应用计数/条件摘要 | CRM 拜访：模式、日期、负责人、客户；模式相关条件随模式切换。 |
| 多字段单据或常用复杂查询 | 视图栏 + 高级筛选 Drawer + ProTable | 可保存筛选、排序、列布局；仅在确实复用查询时出现视图栏 | MES 采购/销售/仓库/质量等单据列表；权限与视图持久化由宿主服务提供。 |
| 树状分类/层级维度反复切换 | 可选固定左侧 Facet | 左侧只放导航式层级/分类；每项更新当前列表范围；窄宽度时变为抽屉或独立弹出面板 | 仅在树层级本身是主要任务且切换频繁时启用；不能把所有低频字段都放左侧。 |
| 宽字段台账 | 工具栏 + 列配置 + 横向滚动 | 默认先显示决策关键列；用户可配置列可见性/顺序；固定列和行操作由列配置声明 | 不用窄小字体把 11+ 字段压成一屏；列持久化由稳定页面 key 隔离。 |
| 可批量处理列表 | 表格选择提示区 | 选择后才出现批量操作与已选数量；批量危险级别、二次确认、失败重试由宿主定义 | 选择提示区紧贴表格，不将批量操作挤进普通筛选栏。无真实批量契约则不显示选择框。 |
| 普通记录新增/编辑 | 表格 + 宿主编辑器插槽 | 短表单 Modal；较长表单 Drawer；复杂流程用独立页面/路由 | 工作台不负责业务校验、保存请求、权限和表单字段。 |
| 单据明细行编辑/批量设值 | `EditableDetailTable` | 行增删改、复制、多行选择、逐字段批量覆盖 | 这是明细组件，不是顶层 ProTable CRUD 变体。 |
| 只读报表/分析列表 | 查询 + 表格/导出 | 可查询、排序、分页、导出；无创建/编辑/删除按钮 | 沿用列表布局，不强制 CRUD 按钮或视图管理。 |
| 任务/状态流转列表 | 分类/状态切换 + 领域动作 | 状态转换由宿主传动作；列表只呈现状态和入口 | 例如待办、商机、任务；不把状态机编码进通用层。 |
| 主从或关联记录视图 | 表格 + 详情/关联区插槽 | 选中行后显示关联信息，或跳转详情；复用行选择和容器插槽 | 只在“选中对象带出关联工作”是实际任务时启用，不普遍做双栏。 |

## 组件结构与职责

### 分层

1. **页面结构层**：复用 `ListScreenContainer`，标题和面包屑属于页面层，结果区工具栏与表格保持邻接。
2. **列表工具栏层**：提供主分类、快捷筛选、搜索、视图和操作的语义槽位；不存在的槽位不占位。
3. **筛选层**：轻筛选继续复用 `FilterBar`；高级筛选用 AntD `Drawer` + 宿主提供的 ProForm/字段内容；高级筛选状态支持未应用草稿。
4. **表格层**：直接渲染 AntD Pro Components `ProTable<T>`；列、请求、分页、排序、行身份和行渲染仍使用上游 API。
5. **可选工作流层**：视图控制器、列配置、批量操作、编辑表单、Facet 侧栏分别以可选能力接入，不做成始终开启的大型状态机。

### 已实现的公开 API

```tsx
<CrudListWorkbench<Product>
  title="产品管理"
  primaryTabs={{ items, value, onChange, ariaLabel }}
  statusFilters={{ items, value, onChange, ariaLabel }}
  quickFilters={<Select /* 少量高频条件，由宿主控制 */ />}
  search={<Input.Search /* 受控值由宿主管理 */ />}
  proTableSearch={{ defaultCollapsed: true, span: { xs: 24, md: 8 }, defaultFormItemsNumber: 3 }}
  advancedFilters={{
    activeCount,
    open,
    onOpenChange,
    children: <ProForm /* 字段与校验由宿主定义 */ />,
    onApply,
    onReset,
    onCancel,
  }}
  viewBar={needsSavedViews ? <SavedViewBar views={views} onChange={applyView} /> : undefined}
  facetSidebar={needsHierarchy ? <Tree /* 树数据与选择由宿主管理 */ /> : undefined}
  toolbarActions={<><Button>分类设置</Button><Button type="primary">新增产品</Button></>}
  tableProps={{ rowKey: 'id', columns, request, pagination, rowSelection }}
/>
```

`tableProps.columns` 和 `rowKey` 必填；`search`、`headerTitle`、`toolbar`、`toolBarRender` 由工作台保留。高级筛选支持受控/非受控打开；应用回调返回 `false` 或抛错时抽屉保留打开并展示恢复提示。保存视图通过独立的 `SavedViewBar` 受控组件提供，所有持久化回调由宿主实现。详情见组件契约。

公开插槽与属性：

- `primaryTabs`：受控高频主分类/业务对象 Tab，可为空。
- `statusFilters`：受控互斥状态，使用本库 `StatusTabs`，可为空。
- `quickFilters`：宿主提供的少量高频条件控件，可为空。
- `search` / `quickFilters`：用于 CRM 式一排快捷控件；空间不足时默认自动折叠，用户展开后置于下一行。可通过 `responsiveQuickFilters={false}` 关闭。
- `proTableSearch`：列 schema 能表达的字段使用 ProTable 原生 QueryFilter；由 ProTable 负责响应式栅格、默认收起及展开交互。
- `advancedFilters`：抽屉入口、`children` 字段内容、应用/重置/取消回调及失败恢复；字段含义由宿主定义。
- `viewBar`：复杂列表可组合 `SavedViewBar`；视图 API/存储由宿主提供。
- `facetSidebar`：可选的树/层级导航插槽，不与 Drawer 混为同一个筛选模式。
- `toolbarActions`：新建、配置、导入等列表级动作；权限过滤由宿主完成。
- `tableProps`：受限的 `ProTableProps<T>`；工作台保留工具栏结构和筛选布局控制权，其余 ProTable 公共能力透传。
- `tableProps.rowSelection`：宿主明确启用后渲染；ProTable 的选择操作区可承载批量动作。
- `toolbarActions`：可放置新增、配置等列表动作；具体表单和 CRUD 处理由宿主实现。

过滤值建议分为三个集合：

- **常驻条件**：最频繁、最能快速缩小集合的关键字/状态/主分类。
- **高级条件**：偶尔组合查询的日期、负责人、客户、组织、编号、扩展属性等。
- **视图快照**：仅保存可序列化且被宿主列入白名单的业务筛选、排序和列偏好；不保存选择行、当前页、抽屉草稿、临时弹窗状态或授权结果。

不要根据 `columns.length` 或筛选字段总数自动切换 UI。宿主显式选择布局；工作台可以提供建议默认项，但布局必须可预测。

## 交互与状态约定

- **条件切换**：主分类、状态、轻筛选或已保存视图改变时回到第一页；请求参数由宿主明确映射，避免 UI 控件值与 API 字段隐式同名耦合。
- **高级筛选草稿**：打开时从已应用条件复制一份草稿；“取消/关闭”不查询且恢复旧值；“重置”只清草稿，点击“应用”后才提交并查询；面板显示已应用条件数。应用后提供简明条件摘要和清除入口。
- **查询失败**：失败结果与反馈仍由宿主/ProTable 请求适配决定；工作台不吞错，也不伪造空结果为成功。
- **视图切换**：有未保存修改时提供“保存并切换 / 放弃修改并切换 / 继续编辑”；保存失败留在当前视图与筛选状态。保存视图存储的作用域（个人、共享、组织）由宿主服务定义。
- **列偏好**：仅在宽表格需要时开放；列状态键按宿主页面稳定标识隔离，默认关键列可见。不能仅为了“功能齐全”给所有小列表增加设置按钮。
- **批量操作**：选中后显示已选数量、清除选择、当前选择范围和可用动作；筛选/翻页后的选择策略由公开配置定义且显式呈现；危险批量操作交给宿主确认和执行。
- **空结果**：文案需区分“当前条件无结果”与“列表确实没有数据”；清除条件或创建入口只在宿主提供且合适时显示。
- **响应式**：桌面宽度保留主分类、状态和主要操作的同一工具栏行；中等宽度允许工具栏换行；窄视口减少常驻条件并将完整条件移至抽屉，表格在结果区内部横向滚动。宽屏 CRM 截图不作为窄屏验收证据。
- **无障碍**：Tab/Segmented 使用真实选中语义；筛选入口带可读名称和已应用计数；图标按钮必须有 `aria-label`；抽屉和 Modal 继续使用 AntD 的焦点管理与键盘交互。

## 实现决策比较

| 方案 | 优点 | 代价/风险 | 决策 |
|---|---|---|---|
| 直接基于 AntD Table 自行开发整套 CRUD | 结构控制最直接 | 必须重做查询联动、远程请求、分页、列搜索、加载和表格动作等通用行为；与当前技术栈重复 | 不选作主要实现 |
| Fork ProTable 源码再改 | 可深入修改内部实现 | 3.x 升级时持续合并上游；MES/CRM 的 2.x 定制无法直接进入目标 3.x；内部实现形成私有分叉 | 不采用 |
| 用 ProTable 公共 API + Sunxu 组合封装 | 保留上游表格/请求能力，集中统一工具栏和筛选/视图结构，升级面较小 | 需守住薄封装边界；公开 API 要跟踪 Pro Components 3 beta 变化 | **推荐** |

Ant Design 是基础控件层，ProTable 是列表引擎，`CrudListWorkbench` 是 Sunxu 的页面组合语义。三层职责不同，不是三选一。

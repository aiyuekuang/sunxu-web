# UX and delivery audit — sunxu-web e907788 and MES modal integration

审查日期：2026-11-20。检查 `e907788` 共享组件修复、MES Admin `58fa2026` 中的 `DocumentModalForm` 全屏弹窗样式修复、依赖锁定和调用点。审查区分已提交代码与工作区遗留内容。

## 1. 范围与证据

**范围：** 表格填充滚动、明细横向溢出、长文本全文入口、批量设置远程候选状态、保存视图栏；销售订单全屏单据弹窗的滚动/圆角改造；以及相关组件在 MES Admin 的依赖和调用链。

**证据：** `e907788` 提交源码和审计报告；该提交干净快照的 `npm run typecheck` 与 `npm run build`；`docs/verification/sunxu-web-component-fixes-2026-11-20/` 的 1440×1000 与 375×390 目录应用截图、DOM 几何 JSON；MES Admin 当前源码、依赖和调用点；全量构建、定向测试、Biome、表格与组件契约检查结果。

**渲染验收：** 共享组件目录中的目标状态有实测证据。销售订单真实路由属于受保护页面，本任务没有经用户确认的测试会话或公开预览路由，按浏览器访问门禁未打开页面；工作区弹窗的 E2/E3 页面验收为 **BLOCKED**。

**未覆盖：** 生产环境实际安装版本、生产数据状态、完整读屏器流程和所有业务路由。此次组件修复没有涉及服务端接口、DTO、权限或持久化。

## 2. 结论

`e907788` 在共享组件层落实了原审计中关于表格滚动、长文本恢复入口和远程 Select 状态反馈的修复，目录实测覆盖滚动到底、窄屏弹窗滚动、加载/错误/重试和窄屏视图栏。MES Admin 的全屏单据表单现将面板尺寸放到 Modal `style`，结构和滚动放到语义 `styles` 插槽；确认发料原生 Modal 也使用同一面板尺寸契约。PDF Drawer 的根、面板、工具栏和正文样式已迁到 Drawer 语义插槽，页面样式不再查询 Modal/Drawer 内部 DOM 类。公式设计器保留窄屏最大宽度约束。

MES Admin 全量构建、定向弹窗测试、表格契约检查、sunxu-web 组件契约检查和本次文件 Biome 检查通过。整仓 `tsc` 仍有 151 条诊断；未发现本次修改文件的直接诊断，诊断包括本地 `sunxu-web` 软链接使 Pro Components/Ant Design 类型从两份 `node_modules` 解析，以及其他业务文件现有的空值类型问题。销售订单真实路由仍因无授权测试会话而不能完成 E2/E3 验收。

依赖仍未完成可复现交付：MES Admin 的 `package.json` 与已跟踪的根 `package-lock.json` 都指向 `d3aaa79`，但该提交只存在于本地 `sunxu-web/main`（领先 `origin/main` 4 个提交）；本机 `node_modules/.package-lock.json` 仍记录 `6e40be20`，`node_modules/sunxu-web` 也仍是本地工作树软链接。没有运行 `npm ci` 或推送远端，因此不能声称其他检出可干净安装。

## 3. 发现

### INT-01 — 依赖锁定与本地软链接不一致

| 维度 | 结果 |
|---|---|
| 类别 | 跨仓集成 / 业务闭环 |
| 严重度 | 高 |
| 证据置信度 | 代码与 Git 状态直接观察 |
| 工作量 | 小至中 |

`mes-admin/package.json` 和已跟踪的根 `package-lock.json` 均 pin 到 `d3aaa79`（`e907788` 的后代）。本机 `node_modules/.package-lock.json` 记录的还是 `6e40be20`（0.4.8）。实际 `node_modules/sunxu-web` 是到 `/Users/suconnect/Desktop/code/sunxu-web` 的软链接，因此本地运行时读取本地工作树 `dist`，不能据此证明干净安装可重现。`sunxu-web` 当前 `main` ahead of `origin/main` 4 commits，`d3aaa79` 不在已跟踪的远端 main 上。MES Admin 多个列表路由使用 `CrudListWorkbench`，`DocumentViewBar` 使用 `SavedViewBar`，长文本与批量设置包装器也调用 `sunxu-web`。

**影响：** 当前开发软链接使组件修复可在本地被引用，但 lockfile/安装记录无法复现此依赖；全仓 TypeScript 检查失败，远端也尚无该依赖提交。目录应用证据不能证明销售订单等真实路由可用。

**处理结果：** 源码声明与已跟踪根 lockfile 的 commit ref 已一致，但依赖 commit 尚未进入远端；本机隐藏锁与软链接是开发环境状态，不能替代干净安装。远端可获取性和 `npm ci` 重现仍为 **BLOCKED**。

**剩余验收：** 在 d3aaa79 可由远端获取且按项目方式干净安装后，重跑消费端类型检查；在用户确认的测试会话或公开预览路由中检查销售订单全屏表单桌面与窄屏状态。

### MODAL-01 — 全屏面板尺寸曾写在 Modal root 插槽（源码已修复）

| 维度 | 结果 |
|---|---|
| 类别 | 滚动 / 布局 / 组件 API 使用 |
| 严重度 | 高 |
| 证据置信度 | 上游 DOM 与类型定义、当前代码直接观察 |
| 工作量 | 小 |

原问题已在源码层修复：`mergeDocumentModalPanelStyle` 将 `top:0`、全宽和全高写入 Modal 面板 `style`；`styles.container/body/header/footer` 分别控制方角、布局、内部滚动和固定操作区；标签页/视口叠层通过 root/mask/wrapper 语义槽定位。原生确认发料 Modal 同样应用面板 style，避免只修包装器调用点。公式弹窗和 PDF Drawer 原有窄屏/全屏样式也保留并迁到公开语义槽。

**源码结果：PASS。** 定向测试检查面板尺寸、零圆角和内部滚动；构建通过。**真实页面结果：BLOCKED。** 没有授权测试会话，未取得页面截图、DOM 几何或滚到底页脚证据，因此不报告视觉验收通过。

## 4. 实现与回归判断

- **滚动与组件规范：** 填充表格和横向溢出检测改用组件语义 `classNames` 插槽标记；测量仍查询组件自己拥有的标记。方向符合共享组件不依赖上游内部 DOM 结构的规范。
- **长文本：** 宽度溢出时增加明确的“更多”恢复入口；换行模式保留悬停、触摸/点击及键盘查看路径。目录证据覆盖宽度溢出和全文对话框。
- **异步状态：** 远程 Select 展示 loading，失败信息放在对应字段旁并提供重试；已有请求序号保护仍在。该组件继续通过宿主传入的 `field.request` 取数，没有新建或改变后端 API。
- **业务语义：** 本提交未见单据字段、权限、保存视图数据协议、查询条件或 patch 提交逻辑变更；从源码差异看没有把业务规则移入共享组件。
- **全屏弹窗：** 源码层面改为公开 Modal 面板 style 和语义 slots；`global.less` 不再使用 `.ant-modal-*`/`.ant-drawer-*` 结构选择器。真实销售订单页面未渲染，保持 BLOCKED。
- **类型检查：** MES Admin `npx tsc --noEmit --pretty false` 失败，输出 151 条诊断。本次修改的 Modal/Drawer 文件没有直接诊断；重复 Pro Components/Ant Design 类型与 symlink 解析位置有关，其余有业务空值类型错误。
- **定向验证：** `npx max build`、本次文件 `Biome check`、`check:table-layout`、`check:sunxu-contract` 通过；Modal 语义样式测试 4 项通过，销售出库视口高度测试通过。销售出库测试文件整体仍有 3 条与本次弹窗改动无关的旧断言失败（视图切换、深链、快筛标签）。
- **依赖闭环：** 根 `package-lock.json` 已跟踪且与 package 声明 ref 一致；远端 main 不含 d3aaa79，本机隐藏安装锁仍旧，未做干净安装验证。
- **业务范围：** 修复只涉及通用 UI 尺寸/滚动/样式挂载，没有改变字段、请求、权限、保存或状态流转；无需后端配套。
- **现有测试覆盖：** 工作区测试主要通过源码文本断言留白和调用标记，没有验证 Modal root 与 dialog panel 的实际尺寸关系，也没有实测滚动区域；无法拦截 MODAL-01。

**共享库构建结果：** `e907788` 干净快照类型检查和构建通过；catalog bundle 仍有约 1.1 MB 的体积提示，不影响构建成功。未运行测试套件。MES Admin 整仓类型检查失败，不能报告消费端类型验证通过。

# 榫序 Web 设计规范

## 产品与首屏任务

Sunxu Web 服务于多个 React Web / PC 管理端项目。主要使用者是前端开发者和设计系统维护者；他们需要快速判断组件职责、找到规范化 API、查看交互状态并复制到宿主页面。目录示例不承担业务数据、接口、路由或权限决策。

主要成功标准是开发者能从目录定位到正确的 Ant Design / Pro Components 组合，并知道哪些状态和业务行为由宿主控制。防止重复封装上游组件是核心护栏。

目录页首屏预算（1440 × 900 CSS px）：

| 区域 | 预算 | 职责 |
|---|---:|---|
| 顶部工具栏 | 56 px | 品牌、组件搜索、主题切换、窄屏导航入口 |
| 左侧导航 | 224 px | 设计规范、组件分类和迁移映射入口 |
| 内容区外框 | 24 px | 保留工作区背景，让主内容面板与导航/工具栏分层 |
| 文档页标题 | 32 px 行高，最多一行 | 识别当前规范或组件分类 |
| 组件预览区 | 首屏优先 | 让使用者直接看到组件状态；不以装饰性介绍挤占空间 |

可用宽度小于 768 px 时，将左侧导航收进抽屉，内容外框改为 16 px；示例表格可在局部横向滚动，页面本身不得产生横向溢出。

## Ant Design 与 Pro Components 的职责

- **Ant Design 6** 是 Button、Input、Select、DatePicker、Modal、Drawer、Menu、反馈和键盘/无障碍基础行为的唯一权威。
- **Ant Design Pro Components 3** 提供 ProTable、ProForm、ProCard、QueryFilter 等列表、表单和内容组合。只有它的 `request` 等公开 props 接收宿主提供的数据函数；Sunxu Web 不内置 API client。
- **Sunxu Web** 维护跨项目可复用的语义主题、页面区块次序、工具栏邻接、滚动区/固定操作区、身份摘要及文档契约。
- 宿主应用拥有数据、查询参数、路由、权限判断、业务文案、操作回调和结果反馈。权限类封装只消费 `permitted` 结果。

当 Ant Design / Pro Components 已满足任务时，直接使用上游 API。扩展一个 wrapper 前，先确认它解决了稳定且跨项目的用户任务，并记录上游直接组合不能满足的具体约束。

## 颜色

颜色保留自 Sunxu 当前语义主题，不采用新项目搜索建议里不相关的靛蓝色。品牌主色在日间为 `#007D35`，夜间为 `#1F7A45`；Ant Design 的算法从 `colorPrimary` 推导交互层级。

| 语义 | Light | Dark | 用途 |
|---|---|---|---|
| Primary | `#007D35` | `#1F7A45` | 主要动作、当前选择、焦点提示 |
| Primary surface | `#E6F7EC` | `#10271A` | 选中/强调的浅背景 |
| Background | `#F5F6F8` | `#0F0F0F` | 工作区 |
| Surface | `#FFFFFF` | `#1C1C1E` | 面板、卡片、输入区域 |
| Text | `#1A1A1A` | `#F5F5F5` | 主信息 |
| Text secondary | `#666666` | `#ABABAB` | 必要的次级信息 |
| Border | `#EBEBEB` | `#2C2C2E` | 分组与边界 |
| Success | `#00B578` | `#00D68F` | 成功状态 |
| Warning | `#FF8F1F` | `#FFAA00` | 警告状态 |
| Error | `#FF3141` | `#FF4D4F` | 错误状态 |
| Info | `#1677FF` | `#4096FF` | 信息状态 |

状态不能只靠颜色表达；表格、徽标和图表还要通过文字、图标、形状或位置传达含义。正文默认使用 Ant Design token 生成的文本颜色，浅灰 `textMuted` 仅用于禁用或非关键装饰信息，不能承担正文。

## 字体与间距

- 中文和拉丁文字使用系统 UI 字体栈，不从远程字体服务下载字体。
- 正文默认 14 px（与 Ant Design 主体密度一致）；说明文本 12–13 px；页面标题 24 px，内容分组标题由 Ant Design 标题层级管理。
- 间距继承 Sunxu 的 4 px 基准：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 px`。页面布局拥有区块之间的 gap；组件仅拥有自身内部间距。
- 桌面标准交互控件高 36 px，紧凑控件 32 px，舒适控件 40 px。Web 指针目标至少 24 × 24 CSS px；图标可以更小，但实际按钮命中区不得小于这一最低值。
- 常用圆角 `4 / 6 / 10 / 14 px`；边线 1 px；不使用重阴影或没有信息层级作用的渐变。
- 动效时长 `150 / 220 / 300 ms`，优先响应状态变化；跟随 `prefers-reduced-motion`。

## 页面与列表

- 页面标题只说明当前任务或对象；已有导航、Tab 或相邻筛选明确主题时，不重复叠加“概览”“信息”等标题。
- 列表级操作、筛选、视图切换和批量动作放在所属结果区紧邻的工具栏；不在页面上方独占远离结果的操作行。
- 复杂列表优先使用 `ProTable`，由宿主提供 columns、数据/请求、行 key、权限可见条件和动作回调；不要另建重复表格抽象。
- 结果、筛选器、分页与选择状态遵守宿主 API 契约。加载、空、错误、成功和过期状态需要在数据语义影响决策时明确呈现。
- 卡片表达可辨认的信息组或独立任务，不把所有控件再嵌进一层卡片。

## 表单与操作

- 表单字段按用户填写顺序组织；使用 Ant Design Form 或 ProForm 的 label、校验和错误呈现。
- 页面较长时只让字段内容滚动，确认/保存/取消等流程操作固定在底部操作区；表单确认按钮不得塞入标题区或随内容滚出视口。
- 短小的新增/编辑任务可以使用 Modal；需要保留列表上下文或较长滚动内容时使用 Drawer；完整工作区才使用独立页面。
- 图标按钮必须提供 `aria-label`；装饰图标从无障碍树隐藏。重要规则和风险不可只放在 Tooltip 中。
- Ant Design 的原生焦点、禁用、加载和弹层行为优先保留；不用通用 CSS 选择器改写库组件内部状态。

## 主题和响应式

`SunxuWebProvider` 使用 Ant Design `ConfigProvider` 的 Light/Dark 算法；如需品牌变更通过语义 token 或 `theme` prop 覆盖，不复制一份局部颜色变量。所有组件需分别检查日间、夜间、窄宽度、长文案和键盘焦点状态。

窄屏时先折叠导航、让工具栏换行和调整内容列；不要靠隐藏决策关键信息适配。复杂数据表可在所属结果面板内横向滚动，不让整页横向漂移。
